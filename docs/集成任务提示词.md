## 三、架构决策（勘察后二选一）

### 路线 A（首选）：CDP + Playwright，零新驱动
ZCode 以调试端口启动后，用 `playwright.chromium.connect_over_cdp("http://127.0.0.1:9223")`
连接既有实例，找到验证码页面，直接调 `solve_on_page_sync(page, selectors=...)`，
按勘察结果填 `Selectors`（四个选择器 + solved/error 探针的 JS 表达式）。
- 优点：整条流程（抓图/定位/换算/拟人拖拽/事件同步）现成，行为特征与 demo 实测一致
- 代价：宿主解释器（3.14）需安装 playwright + `python -m playwright install chromium`
  （连接 CDP 不需要下载的内核也能连，但装齐可避免坑）；启动参数需带调试端口

### 路线 B：屏幕截图 + SendInput 拖拽（CDP 不可用时）
**不要硬凑 JS 探针**。复用两个与传输层无关的纯函数：
1. 截取验证码区域（注意 DPI：UIA 坐标是逻辑坐标，GDI/截图是物理像素，
   本机 150% 缩放，务必用 `system_dpi_scale()` 换算，并在截图进程开 DPI 感知），
   裁出背景图与拼图块 → `find_gap(bg, piece)` 得到 `Gap`
2. `build_choreography(distance)` 得到动作序列，用 SendInput 解释执行：
   `('down',)`→MOUSEEVENTF_LEFTDOWN，`('move',x,y)`→SetCursorPos/SendInput 绝对坐标，
   `('up',)`→LEFTUP，`('sleep',ms)`→time.sleep；拖动起点=滑块中心物理坐标
3. 成功判定用勘察确认的图像信号（区域像素对比或成功标记模板），
   失败则按配置重试，超过上限走人工回退
